Exact install, preflight, build and run commands

Run the following in a WSL login shell. The pinned Docker package block changes system packages: use it only when preparing the host, with the official Docker Ubuntu apt source configured and the exact versions available. The Python check skips downloading when 3.12.14 is already installed; uv sync --frozen creates the project environment from the lockfile.

set -euo pipefail
sudo apt-get update
sudo apt-get install --no-install-recommends \
  'docker-ce-cli=5:29.8.2-1~ubuntu.24.04~noble' \
  'docker-ce=5:29.8.2-1~ubuntu.24.04~noble' \
  'docker-buildx-plugin=0.37.1-1~ubuntu.24.04~noble'

mkdir -p ~/src
cd ~/src
git -c core.autocrlf=false clone https://github.com/LuxuriantTech/postgres-migration-rehearsal.git pmr-v2
cd pmr-v2
git checkout --detach 626072c0eac87f0b05c287c51f9cc5f150299c9e
uv python find 3.12.14 >/dev/null 2>&1 || uv python install 3.12.14
uv sync --frozen
uv run --frozen python --version
dpkg-query -W docker-ce-cli docker-ce docker-buildx-plugin
docker context show
docker context inspect default --format '{{.Endpoints.docker.Host}}'
sha256sum /usr/bin/docker /usr/bin/dockerd /usr/libexec/docker/cli-plugins/docker-buildx
docker buildx version
docker buildx inspect --bootstrap
PYTHONPATH=src:scripts uv run --frozen python scripts/verify_docker_repository_provenance.py

pmr_tmpdir="$(mktemp -d "${TMPDIR:-/tmp}/pmr-demo-v2.XXXXXX")"
trap 'rm -rf "$pmr_tmpdir"' EXIT
docker buildx build --platform linux/amd64 --no-cache --provenance=false \
  --build-arg SOURCE_DATE_EPOCH=1788825600 \
  --output "type=oci,rewrite-timestamp=true,dest=$pmr_tmpdir/image.oci.tar" \
  --metadata-file "$pmr_tmpdir/build.json" runtime-baselines/demo-20260908
PYTHONPATH=src:scripts uv run --frozen python scripts/verify_demo_baseline_v2_build.py \
  "$pmr_tmpdir/build.json"
docker load -i "$pmr_tmpdir/image.oci.tar"
PYTHONPATH=src:scripts uv run --frozen python scripts/rehearse_baseline_v2.py --preflight-only
PYTHONPATH=src:scripts uv run --frozen python scripts/rehearse_baseline_v2.py --scenario small-shop \
  | tee /tmp/pmr-demo-v2-result.json

The last command prints and saves a fresh JSON result. The runner itself performs rollback to the original schema, rolls forward through contract, and cleans only its own labelled resources. Check the return state:

docker ps -a --filter name=pmr-demo-v2-
docker network ls --filter name=pmr-demo-v2-

The optional package block prepares the host; the remaining commands verify the runtime and run the bounded rehearsal. If the package versions, executable hashes or context differ, stop at preflight and follow the signed package evidence; do not edit the manifest. If the build verifier reports a manifest, config, platform or material mismatch, do not load that image.

The deliberate rejection route is --scenario invalid-negative-amount. It exits with Amount must be a positive whole number of cents. before preflight or resource creation; this is an expected input error. After a successful run, expect LOCAL_REHEARSAL_PASSED, restored legacy rows, completed roll-forward, cleanup_state: complete, owned_resources_remaining: 0, and historical_phase_b_replayed: false.

Five ordered stages

1. Expandadd nullable target columns
2. Compatibilityallow temporary old and new write shapes
3. Backfillresume small batches; check idempotence
4. Switchmove reads and writes to the target shape
5. Contractremove the legacy column after the boundary closes

The bounded example

The primary example is a six-invoice synthetic local run. It is distinct from the historical 4,096-row development demonstration. Historical Phase B is a frozen, one-shot record with no browser run control and is not rerun here.

Failure states matter

A deliberately invalid synthetic scenario is rejected before database work. A deterministic error fixture shows that an unconfirmed cleanup blocks another run; it is not evidence of a failed real migration.
